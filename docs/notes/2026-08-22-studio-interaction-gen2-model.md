# Studio Interaction & Perceptual Information Architecture Model (Gen2)

**Date**: 2026-08-22  
**Status**: Isolated Author Proposal (Phase IV Gen2 Model)  
**Scope**: Perceptual and Information-Architecture Model for Lattice Studio  
**Context**: Reconstructs interaction architecture from first principles following the Chair Note (`docs/notes/2026-08-22-studio-interaction-chair-note.md`), eliminating gen1 affordance collisions, synthetic UI-only entities, and widget-driven domain distortions.

---

## 1. Executive Frame & Architectural Invariants

Lattice is an AI-native declarative video editing system where project state is text-first (`.vel`), deterministic, and Git-friendly. Studio is an `Engine` client, not a standalone NLE application with private domain state.

This document establishes the **Gen2 Perceptual & Information-Architecture Model** for Lattice Studio. It addresses how the screen teaches the user and external coding agents about semantic identity ("here"), temporal observation ("when"), legal action ("what can be changed and at what scope"), and absence ("why something is not visible or editable").

### Non-Negotiable Invariants
1. **One Shared Locus as Semantic "Here"**: A single `LocusId` defines editing identity across VEL source, Canvas, Timeline, Review, Inspector, and Agent context. No view owns a private semantic selection.
2. **Engine Client Architecture**: Studio commits user intent via `SemanticEdit`s and source rewrites through `lattice-engine`. No GPUI types leak into `lattice-core`.
3. **No Hidden Magic or Widget-Driven Domain Distortion**: Domain semantics are never warped to accommodate UI widgets or tree views. All expansions are explainable via `lattice explain`.
4. **Text-First & Git-Friendly**: No project database. Volatile Undo/Redo is source-backed.
5. **Separation of Phases**: Compile, Resolve, Evaluate, Render, and Encode remain strictly decoupled.

## 2. What "Here" Is: Locus as Singular Semantic Intention

### 2.1 The Definition of Locus
In conventional NLEs, selection is **object-centric and spatial-temporal**—selecting a specific rectangle on a specific video track at a specific time. In Lattice, editing intent is **definition-centric and semantic**.

A **Locus** (`lattice-core::Locus`) is the singular semantic entity being pointed at. It represents the shared identity of a construct declared in VEL or generated by lowering.
- One definition written in VEL (e.g., `title "Hello"`) may project into:
  - An AST span in VEL source.
  - One or more timeline clips across scene boundaries.
  - A visual overlay in normalized Canvas coordinates.
  - A target for external coding agents (`locus + instruction`).
- The Locus is **the meaning and identity**, not any single rendered bounding box.

### 2.2 Projections of Locus
A Locus is projected into views according to available facets:
```text
                  ┌────────────────────────────────────────┐
                  │          Locus (Semantic Here)         │
                  │   id: LocusId, kind: LocusKind         │
                  │   provenance: Provenance, origin: Span │
                  └───────────────────┬────────────────────┘
                                      │
         ┌──────────────┬─────────────┼──────────────┬──────────────┐
         ▼              ▼             ▼              ▼              ▼
   [VEL Source]     [Timeline]     [Canvas]      [Inspector]     [Agent]
    Source Span     Clip Spans     Overlay       Action Inventory Context
    (Provenance)    (TimeSpan)   (evaluate_at)   (SemanticEdit) (Locus+Prompt)
```
- A projection is **facet-based**: if a locus has no visual representation (e.g. `Sequence` or audio-only `Source`), Canvas does not project a bounding box, but the Locus remains valid across Timeline, Source, and Inspector.
- Selecting a projection in any surface immediately updates the session's single `current: Option<LocusId>`, which reflects across all active projections without creating secondary selections.

## 3. Playhead vs. Locus: Orthogonality of "When" and "Here"

One of the primary failure modes of gen1 interaction was the conflation of **temporal observation** (Playhead) and **semantic focus** (Locus).

### 3.1 Strict Separation of Roles
| Dimension | Concept | Type / Storage | Interaction Meaning | Mutates Source? |
|---|---|---|---|---|
| **When** | **Playhead** | `Time` (Session state) | The temporal coordinate where Canvas and Audio evaluate (`evaluate_at(t)`). Transient transport state. | **No** (Scrub/Seek does not rewrite VEL or push Undo). |
| **Here** | **Locus** | `LocusId` (Session state) | The semantic entity targeted for inspection, direct manipulation, or agent instructions. | **No on point**, **Yes on commit** (commits a `SemanticEdit`). |

### 3.2 Scrubbing and Pointing Contracts
In gen1, scrubbing the timeline silently invoked `point_from_timeline_time(t)` using `max_by_key(specificity)`, unintentionally switching the semantic locus as a side effect of time navigation.

In Gen2:
1. **Scrubbing Moves ONLY the Playhead**: Dragging the timeline ruler or rail background adjusts `playhead: Time`. It does **not** alter `current: Option<LocusId>`.
2. **Pointing is an Explicit User Gesture**: Clicking a clip body or source span explicitly sets the `Locus`.
3. **Canvas Evaluation at Playhead**: Canvas renders the scene evaluated at `playhead`. If the selected Locus has an active visual overlay at `playhead`, the overlay bounding box with interactive handles is rendered.
4. **Off-Time Locus Disclosure**: When a Locus is selected whose temporal lifespan does not include `playhead` (e.g., Title active at `[1.0s, 3.0s]` while `playhead` is at `0.0s`):
   - Canvas renders the frame at `playhead` (e.g., video background at `0.0s`).
   - An informative non-blocking status badge indicates: `Locus "Hello" active at 00:01.000 - 00:03.000 (Playhead at 00:00.000)`.
   - A 1-click action `[Jump Playhead to Locus]` is presented.
   - **No automatic silent seek** occurs upon selection.

## 4. How Legal Verbs Appear: The Action Inventory Model

Gen1 suffered from "title-shaped Inspector controls" where selecting a Scene or Source presented Title text inputs due to fallback heuristics (`adopt_locus_label` / `target_scene_locus`).

### 4.1 Engine-Derived Action Inventory
In Gen2, the Inspector and toolbar are not static property forms. They represent an **Action Inventory** dynamically computed by `lattice-engine` from the active `Locus` and `Compilation`.

For any selected `Locus`, `lattice-engine` exposes:
1. **Semantic Identity & Provenance**: `label`, `kind`, `node_id`, `origin`, `source_span`.
2. **Supported `SemanticEdit`s with Explicit Target Scopes**:
   - `Title`: Edit text, start time `at`, `duration`, `opacity`. (Scope: *Definition* or *Placement*).
   - `SetPosition` / `ResizeOverlay`: Move/scale normalized coordinates. (Scope: *Placement*).
   - `Trim`: Adjust `in_point` / `out_point`. (Scope: *Source Clip*).
   - `Split`: Split clip at time. (Scope: *Source Clip*).
   - `ReorderScene`: Reorder sequence. (Scope: *Sequence Flow*).
   - `SetGain` / `SetFade`: Audio gain / video fade. (Scope: *Source* or *Media*).
   - `Delete`: Remove construct. (Scope: *Definition*).
3. **Unavailable Actions with Explicit Reasons**: E.g., for a `Sequence` locus: *"Spatial positioning is unavailable because Sequence has no visual coordinate projection."*

### 4.2 Explicit Edit Scoping
Every affordance and verb explicitly displays its mutation scope:

```text
┌─────────────────────────────────────────────────────────────┐
│ LOCUS: Title "Gameplay Commentary"                          │
│ Provenance: main.vel:16:3 (Invocation: title)               │
├─────────────────────────────────────────────────────────────┤
│ LEGAL VERBS                                                 │
│ • [Edit Text]         → Scope: Definition (main.vel:16)     │
│ • [Reposition Canvas] → Scope: Placement (scene:intro)      │
│ • [Adjust Timing]     → Scope: Timeline Clip (00:01–00:04)  │
│ • [Delete]            → Scope: Ast Node                     │
└─────────────────────────────────────────────────────────────┘
```

If an action targets an ancestor (such as deleting the containing scene when clicking a clip), the interface explicitly discloses: `Target: Scene "intro" (parent of selected clip)`. It never executes a quiet fallback.

## 5. Overlap & M10 Policy: Disambiguated Candidates vs. Specificity

### 5.1 The Overlap Problem
At time `t = 2.0s`, a single coordinate in the timeline may intersect:
1. `Sequence` (e.g., `main`)
2. `Scene` (e.g., `scene_1`)
3. `Source` (e.g., `gameplay_video`)
4. `Placement` / `Title` (e.g., `title "Watch this"`)

In gen1, `Engine::locus_at_timeline` collapsed this candidate set using an arbitrary numerical rank:
`specificity(Title: 4) > specificity(Source: 3) > specificity(Placement: 2) > specificity(Scene: 1)`.

This manufactured a singular selection without user consent, leading to confusing accidental selections and misattributed actions.

### 5.2 Gen2 Disambiguation Policy
1. **Explicit Hit Targets**:
   - Clicking directly on an overlay in the Canvas selects that exact visual `Placement` / `Title`.
   - Clicking on a clip track in the Timeline selects the clip of that specific track.
   - Clicking an AST node in VEL selects that specific source construct.
2. **Ambiguous Pointing (e.g. Point from Time or Click on Shared Rail)**:
   - When pointing from an unlayered time coordinate where multiple loci intersect, the system evaluates all intersecting candidates: `candidates = loci.filter(|l| l.contains_time(t))`.
   - If `|candidates| == 1`: Selects that locus directly.
   - If `|candidates| > 1`: The highest-specificity locus is focused as the *provisional default*, while the Inspector / Header presents a compact **Breadcrumb / Disambiguation Segment**:
     ```text
     [ Sequence: main ] > [ Scene: intro ] > [ Video: game.mp4 ] > [ ★ Title: "Watch this" ]
     ```
   - Clicking any ancestor in the breadcrumb immediately switches the shared `LocusId` to that level of the hierarchy.
   - This preserves instant 1-click usability while eliminating hidden selection heuristics.

## 6. How Absence is Disclosed: The Cause-Attributed Absence Taxonomy

In gen1, an empty Canvas or a missing Inspector field appeared as an opaque black box or silent omission, leaving the user unable to tell if the system was broken, loading, or functioning as designed.

Gen2 mandates an **Explicit Absence Taxonomy**:

```text
┌─────────────────────────────────────────────────────────────────────────┐
│                           ABSENCE TAXONOMY                              │
├───────────────────────┬──────────────────────┬──────────────────────────┤
│ Surface & Symptom     │ Root Cause           │ Disclosed Explanation    │
├───────────────────────┼──────────────────────┼──────────────────────────┤
│ Canvas is Black       │ 1. Off-Time Locus    │ "Locus active at 1s–4s;  │
│                       │                      │  Playhead at 0s. [Seek]" │
│                       │ 2. Preview Off       │ "Preview disabled        │
│                       │                      │  (PREVIEW=0)"            │
│                       │ 3. Renderer Init     │ "Initializing GPU/CPU    │
│                       │                      │  renderer pipeline..."   │
│                       │ 4. Missing Media     │ "Media file missing:     │
│                       │                      │  assets/game.mp4"        │
│                       │ 5. Compile Error     │ "Compile error:          │
│                       │                      │  main.vel:12: missing {" │
│                       │ 6. Empty Scene       │ "No visual placements at │
│                       │                      │  current playhead"       │
├───────────────────────┼──────────────────────┼──────────────────────────┤
│ Inspector Blank / No  │ Non-visual /         │ "Locus 'Media' has no    │
│ Transform Controls    │ Immutable Locus      │ spatial or text fields.  │
│                       │                      │ Actions: [Replace Media]"│
├───────────────────────┼──────────────────────┼──────────────────────────┤
│ Timeline Clip Missing │ Synthetic Lowering / │ "Derived transform       │
│ Span                  │ Virtual Node         │ without linear duration" │
└───────────────────────┴──────────────────────┴──────────────────────────┘
```

No black frame or empty pane is ever rendered without an explicit, queryable status state.

## 7. Direct Manipulation & Gestural Lifecycle

All interactive modifications in Studio follow a strict four-phase lifecycle ensuring safety, determinism, and atomic Undo:

```text
  [Pointer Down] ──► [Begin Gesture]
                           │
                           ▼
  [Pointer Move] ──► [Update Ephemeral State] (Canvas / Timeline redraw only)
                           │
              ┌────────────┴────────────┐
              ▼                         ▼
   [Pointer Up: Commit]          [Escape: Cancel]
   • Validate constraints        • Discard ephemeral state
   • Build 1 SemanticEdit        • Restore compiled geometry
   • Apply 1 Source Rewrite      • VEL unchanged
   • Compile & Record 1 Undo     • Zero Undo entry added
```

### Hit-Region Segmentation (M4)
To avoid dual-mode confusion on the Timeline:
1. **Ruler / Rail Background**: Pure Scrub (`TimelineGesture::Scrub`). Moves playhead only.
2. **Clip Body**: Pointer-down selects `Locus`. Dragging beyond `DRAG_THRESHOLD_PX` (4px) begins semantic move/reorder (`MoveOverlay` or `ReorderScene`).
3. **Clip Edge (Trim Handles)**: Dragging within `TRIM_HANDLE_PX` (8px) of left/right edges begins semantic trim (`Trim` or `ResizeOverlay`). Edge cursor (`CursorKind::Trim`) indicates affordance before click.

## 8. Review Model: Broad Semantic Diffing Without Mandatory Gating

In gen1, Review was restricted to Title text edits and presented only a raw textual diff.

### 8.1 Expanded Scope of Review (M7)
Review operates on any `EditProposal`. It is capable of projecting proposals across all `SemanticEdit` variants:
- **Spatial Edits** (`SetPosition`, `ResizeOverlay`): Shows before/after bounding box coordinates and canvas thumbnail preview.
- **Timing Edits** (`Trim`, `Split`, `ReorderScene`): Shows span changes on the timeline.
- **Text & Property Edits** (`Title`, `Callout`, `SetGain`): Shows property diff and source diff.

### 8.2 Non-Gating Workflow
- Direct manipulation (canvas drag, timeline trim) commits atomically via `pointer_up` without forcing a modal Review dialog.
- External coding agents submit proposals that populate the `Review` panel (`description`, `vel_diff`, `before/after preview`, `base_revision`).
- User can explicitly trigger Review on any staging action before applying.
- Source is atomically updated only upon `Apply`; `base_revision` mismatch detects stale edits safely.

## 9. Evaluation of Mutation Ledger (M1–M10)

| Mutation | Decision | Justification |
|---|---|---|
| **M1: Projection Inventory** | **ADOPT** | Discloses all available Core/Engine facets (source, time, visual, actions) without multiplying panes or inventing synthetic `LocusKind`s. Explains partial projection naturally. |
| **M2: Independent Locus & Playhead** | **ADOPT** | Decouples time navigation from semantic targeting. Scrubbing never mutates the locus; off-time locus is disclosed with an explicit seek action. |
| **M3: Scope-Labelled Legal Verbs** | **ADOPT** | Replaces static Inspector fallback forms with Engine-validated `SemanticEdit` actions, each tagged with its exact scope (`Definition`, `Placement`, `Clip`). Fails closed for unsupported edits. |
| **M4: Timeline Hit-Region Split** | **ADOPT** | Enforces non-overlapping interaction regions: rail background scrubs, clip body selects/moves, clip edge trims. Rest-state cursor affordance prevents ambiguous pointer behavior. |
| **M5: Multiplicity Probe** | **ADOPT** | Uses verified 1→many fixtures. Discloses instance counts and definition links cleanly without requiring deceptive simultaneous track highlighting across unrelated scenes. |
| **M6: Freeze Honesty** | **ADOPT (Variant A/Honest Exposure)** | Rejects synthetic `Core Freeze` or artificial tree nodes (`freeze:source:clip`). Freeze is an explained rate-0 segment on a Source `TimeMap`, inspected through Source/TimeMap semantics. |
| **M7: Review Breadth** | **ADOPT** | Generalizes `EditProposal` projection beyond title text to include canvas placement, trim, and scene reordering, without turning Review into a mandatory roadblock for direct manipulation. |
| **M8: Role & Width Harness** | **ADOPT (As Evaluation Constraint)** | De-conflicts visual roles (Locus vs Playhead vs Status vs Selection) and ensures graceful degradation under viewport constraints without dropping core functional surfaces. |
| **M9: Canvas Absence Taxonomy** | **ADOPT** | Categorizes empty Canvas into six distinct root causes (Off-time, Preview-off, Initializing, Missing Media, Compile Error, Empty Scene) with visible explanations. |
| **M10: Overlap Disambiguation** | **ADOPT** | Replaces silent `max_by_key(specificity)` collapse with interactive breadcrumb disambiguation, preserving one shared locus while preventing accidental selection jumps. |

## 10. The Decisive Falsifier

Any architectural model must state what empirical evidence would falsify it.

### Falsification Test
> **Falsifier**: If an editor in a user study navigating a timeline with overlapping media and overlays repeatedly attempts to scrub by dragging clip bodies—or fails to recognize that a spatial edit on a shared `Title` definition mutates placement across all scenes—and introducing modal tools (e.g. dedicated "Selection Tool" vs "Razor Tool" vs "Hand Tool") or per-view selection resolves the error rate where the unified locus and hit-region segmentation failed, then the assumption that a single non-modal locus and region-segmented timeline are sufficient for dense editing is **falsified**.

If this falsification condition is met, Lattice would be forced to reconsider explicit editing modes or view-local interaction contexts. Until such evidence is demonstrated, the Gen2 unified locus model preserves maximal semantic integrity with minimal cognitive friction.
